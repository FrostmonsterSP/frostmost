# FrostMost — спецификация UX/UI изменений

**Версия:** 2.0  
**Дата:** 2026-11-08  
**Статус:** целевая спецификация для реализации  
**Связанный документ:** `FrostMost-Design-Map-v2.md`

## 1. Цель

Упростить главный экран FrostMost, сохранив возможности v2rayNG и не меняя сетевую логику.
Пользователь должен видеть состояние VPN и основные действия постоянно, а серверы и маршрутизацию
настраивать inline, без серверной bottom sheet.

## 2. Приоритеты

- **P0 — корректность и безопасность:** импорт, состояния VPN/сервера/подписки, ошибки и секреты.
- **P1 — архитектура главного экрана:** неподвижная зона подключения, inline-секции routing/servers.
- **P2 — доступность и адаптивность:** TalkBack, крупный шрифт, IME, клавиатура и компактные экраны.
- **P3 — проверка удобства:** тестирование на реальных устройствах и исправление проблем.

## 3. P0 — корректность поведения

### 3.1 Разделение состояний

VPN, подписка и сервер — независимые сущности. UI не должен выводить состояние одной сущности
из другой без подтверждённого основания.

Минимально различать:
- VPN отключён;
- подключение выполняется;
- VPN подключён;
- переключение сервера;
- остановка/ошибка запуска;
- подписка обновляется;
- подписка просрочена или исчерпала трафик;
- выбранный сервер недоступен — только если это подтверждено отдельной проверкой.

### 3.2 Импорт подписки

- Имя новой подписки брать из `Profile-Title`, если заголовок присутствует.
- Повторный импорт той же ссылки должен быть идемпотентным и не создавать дубликаты.
- Импорт ссылки не должен сам включать VPN.
- Импорт ссылки не должен переключать уже работающий VPN на новую подписку/сервер.
- Во время загрузки показывать явное состояние, а не пустой экран.
- Ошибка должна сохранять введённую ссылку и давать понятное действие для повтора.
- Обновлять только требуемую подписку; не запускать без необходимости обновление всех подписок.

### 3.3 Секреты и журналирование

Никогда не записывать в логи:
- полные URL подписок;
- credentials и токены;
- приватные ключи;
- экспортированные конфигурации.

Ошибки логировать с названием операции, компонентом/режимом, безопасным стабильным ID при наличии
и исключением без секретных данных.

### 3.4 Ошибки

Сообщение должно отвечать на три вопроса:
1. Что произошло?
2. Что пользователь может сделать?
3. Какое действие исправит проблему?

Не показывать «сервер не отвечает» только на основании факта запуска ядра. Для такого статуса
нужен достоверный результат отдельной проверки.

## 4. P1 — архитектура главного экрана

### 4.1 Разделение на две зоны

Реализовать **Fixed Connection Area + Scrollable Configuration Area**.

**Неподвижная зона:**
1. Top bar;
2. ряд подписок, если их больше одной;
3. карточка подписки с VPN-действием и статусом;
4. быстрые действия;
5. актуальное сообщение/проблема, если есть.

**Прокручиваемая зона:**
1. раскрываемая секция «Маршрутизация»;
2. раскрываемая секция «Серверы».

В обычном портретном режиме прокрутка конфигурации не должна уносить с экрана VPN-карточку
и основные действия.

### 4.2 Требования к неподвижной зоне

- Не задавать фиксированную общую высоту.
- Не резервировать место под пустое сообщение.
- Длинные сообщения показывать превью с раскрытием.
- Не обрезать текст и не уменьшать системный font scale.
- Основная VPN-кнопка остаётся визуально доминирующей.
- При отсутствии объявления верхняя зона автоматически становится компактнее.

### 4.3 Секция «Маршрутизация»

- Заголовок показывает название секции, выбранный режим и индикатор раскрытия.
- Список вариантов раскрывается inline.
- Выбранный вариант имеет явное selected state, доступное не только по цвету.
- После выбора заголовок показывает новое значение.
- Сохранить существующие режимы, алгоритм, порядок и формат хранения.
- Не менять семантику выбора без отдельного согласования.

### 4.4 Секция «Серверы»

- Заголовок показывает название секции и выбранный сервер.
- Список раскрывается inline, без серверной `ModalBottomSheet`.
- В раскрытом состоянии доступны поиск, проверка и список.
- Основная область строки выбирает сервер.
- Поделиться/изменить/удалить перенести в overflow menu.
- Удаление требует отдельного явного действия и не должно срабатывать при выборе строки.
- Выбранный сервер имеет доступное текстовое/иконное обозначение.
- Адрес, порт, протокол и транспорт — вторичная информация.
- Перезапуск доступен только при активном VPN; disabled-состояние объясняется accessibility-текстом.
- Проверка не меняет выбор сервера и не запускает VPN.
- Не показывать неподтверждённую недоступность сервера.

### 4.5 Прокрутка и идентичность

- В обычном режиме использовать одного владельца вертикальной прокрутки.
- Не вкладывать вертикальный список серверов в вертикальный scroll container без обоснования.
- Предпочтителен единый lazy list с секциями.
- Использовать GUID сервера и ID группы как стабильные ключи.
- Не использовать индекс списка как идентичность.
- Раскрытие/сворачивание не должно сбрасывать выбранную подписку, сервер, routing mode и VPN.
- Сохранять поисковый запрос и позицию списка при временном сворачивании, пока жив экран.

### 4.6 Удаляемый паттерн

Удалить с главного экрана:
- серверный `BottomSheetScaffold`;
- peek-состояние шторки серверов;
- пользовательскую ручку перетаскивания шторки;
- переход к списку серверов через отдельный modal bottom sheet.

Не удалять независимые модальные сценарии добавления подписки и других самостоятельных задач.

## 5. P2 — адаптивность и доступность

Обязательные сценарии проверки:
- ширина 320 dp;
- компактная высота;
- landscape;
- split-screen / multi-window;
- font scale 1.3× и 2.0×;
- TalkBack;
- клавиатура и D-pad;
- открытая IME в поле поиска;
- системный Back.

Если верхняя зона не помещается:
- разрешить прокрутку всего экрана единым контейнером; или
- открыть конфигурацию на отдельном полноэкранном destination.

Не уменьшать системный размер шрифта и не скрывать основные действия.

Все видимые строки и accessibility labels должны быть Android resources. Обновить все локали,
заданные в `localeFilters` (для проекта — `en` и `ru`), сохранив placeholders и plurals.

## 6. Сохранение функциональности и границы

Не менять в рамках этой задачи:
- VPN-ядро и сетевые протоколы;
- алгоритмы маршрутизации;
- форматы подписок, сериализованные поля и persisted schema;
- форматы импорта/экспорта;
- режимы VPN / proxy-only / root;
- виджет и плитку быстрых настроек.

Не выполнять несвязанные рефакторинги и обновления зависимостей.

## 7. Критерии приёмки

### P0
- [ ] VPN, подписка и сервер имеют независимые и понятные состояния.
- [ ] `Profile-Title` используется как имя импортируемой подписки.
- [ ] Повторный импорт не создаёт дубликат.
- [ ] Импорт не включает VPN и не переключает текущий VPN.
- [ ] Ошибки импорта и обновления объясняют причину и следующее действие.
- [ ] Секреты и полные URL подписок отсутствуют в логах.

### P1
- [ ] На обычном портретном экране верхняя зона остаётся видимой при прокрутке конфигурации.
- [ ] Сообщение не занимает место, когда его нет.
- [ ] Routing раскрывается inline.
- [ ] Servers раскрывается inline; серверный bottom sheet удалён.
- [ ] В обычном режиме нет вложенных вертикальных scroll containers.
- [ ] Поиск, выбор сервера и overflow-действия работают независимо.
- [ ] Выбор сервера не включает VPN неожиданно.
- [ ] Сворачивание секций не сбрасывает пользовательский контекст.

### P2
- [ ] Нет обрезания при увеличенном шрифте.
- [ ] Все интерактивные элементы имеют понятные TalkBack labels и state descriptions.
- [ ] Все действия доступны клавиатурой/D-pad.
- [ ] IME не перекрывает поле поиска.
- [ ] На компактных экранах работает адаптивный fallback.
- [ ] Back не отключает VPN.

## 8. План реализации

1. Проверить текущие владельцы состояния главного экрана и списка серверов.
2. Спроектировать единый scroll owner для конфигурационной зоны.
3. Перенести routing selector в inline expandable section.
4. Перенести список серверов в inline expandable section.
5. Перенести вторичные действия строки в overflow menu.
6. Удалить серверную bottom sheet и связанный peek-state.
7. Сохранить query, selected server, selected subscription и позицию списка.
8. Добавить адаптивный fallback.
9. Проверить TalkBack, keyboard/D-pad, IME, Back и восстановление состояния.
10. Выполнить unit tests и сборку по правилам проекта; runtime-сценарии проверить на устройстве.

## 9. Проверки разработки

Для изменённой детерминированной логики добавить/обновить JUnit tests в
`V2rayNG/app/src/test/java/`.

Для Kotlin/Java кода выполнить:
- тесты, проверяющие изменённое поведение;
- `:app:testPlaystoreDebugUnitTest`;
- `:app:compilePlaystoreDebugKotlin`.

Для ресурсов/manifest/Gradle/dependencies выполнить `:app:assemblePlaystoreDebug`.
Для изменений accessibility, focus, IME, state restoration и системной навигации дополнительно
провести проверку на эмуляторе или физическом устройстве.

Невыполненную проверку явно обозначить как **Not run** с командой/сценарием и причиной.
Компиляция или собранный APK сами по себе не подтверждают runtime-поведение.
