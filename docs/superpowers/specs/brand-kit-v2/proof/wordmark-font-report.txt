------------------------------------------------------------
1. FONT AND INSTANCE
------------------------------------------------------------
File on disk   : /usr/share/fonts/inter/InterVariable.ttf  (variable font, upm 2048)
Instance       : wght=600, i.e. Inter SemiBold
Instance method: fontTools.varLib.instancer.instantiateVariableFont(font, {"wght": 600})
Tracking       : -0.02em applied per glyph advance (TRACKING_EM = -0.02)
Cap height     : 0.7275 em (OS/2 sCapHeight 1490 / 2048) — used for all vertical maths
x-height       : 0.5459 em (OS/2 sxHeight 1118 / 2048)

Inter.ttc was NOT used. The variable TTF was instanced at 600 so the weight is exact
rather than a named instance resolved by the rasteriser, which keeps the outline data
identical on every machine.

------------------------------------------------------------
2. HOW THE CURVES WERE PRODUCED (method, and why)
------------------------------------------------------------
Method: direct glyph outline extraction — NOT raster tracing.

  fontTools TTFont -> instantiateVariableFont(wght=600) -> glyphSet().draw(TransformPen(SVGPathPen))
  Each glyph is drawn through a TransformPen with matrix (1/upm, 0, 0, 1/upm, pen_x, 0),
  so the emitted commands are already in em units with the pen advance baked in.

Why this and not magick + potrace: potrace 1.16 is installed and was considered, but
it reconstructs quadratics from a raster and inevitably softens the flat-sided counters
and the crisp stems of a grotesque. Extracting the font's own cubic Bezier outlines is
exact, resolution-independent, and reproduces the typeface bit-for-bit instead of
approximating it. No interpolation or smoothing step exists to melt the shapes.

Rendering was used only to VERIFY, never to produce, the geometry: the traced paths were
rasterised with rsvg-convert and measured back (section 3). Rendered ink matched the
predicted bbox to within anti-aliasing tolerance, and the letters read as genuine
Inter SemiBold (see proof/wordmark-horizontal-name24-x4.png).

The nine glyph paths are outlines only; no glyph is a bitmap, and every path is closed
contour data in the source font's own cubic format.

------------------------------------------------------------
6. PLACEHOLDER MARK — COORDINATION NOTE
------------------------------------------------------------
The <g id="mark"> block in BOTH files currently contains wordmark-owner's own
placeholder approximation of the symbol, not mark-designer's final geometry. It obeys the
contract's numbers (ink 14..86 on a 100-unit canvas, 2 closed forms, strokes >= 5,
symmetric about x=50) so the surrounding spacing is already correct, but it must be
replaced.

The final geometry must be swapped INSIDE <g id="mark"> only. The transform on that group
(translate + scale) and the name group must be left untouched, because the measured
margins above depend on the mark's ink occupying 14..86 of its 100-unit box. If the final
mark's ink sits elsewhere in its box, re-run the builder so the gap stays 9 units.
